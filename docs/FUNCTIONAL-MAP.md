# Mapa Funcional — Protótipo → Arquitetura Alvo

Mapeamento de cada elemento do protótipo (`projeto_solicitacao_credito_atualizado_v3.html`) para o componente, entidade e API alvo da nova arquitetura (React/NestJS/PostgreSQL), conforme pedido em `especificacoes_sistema_credito_rural/01-AUDITORIA-E-REQUISITOS.md`.

Referências de linha do protótipo são citadas em cada célula da coluna "Protótipo". Entidades seguem a lista candidata da spec 03 (`00-CONTEXTO-PROJETO.md`/`03-DOMINIO-E-WORKFLOW.md`); nomes de endpoints são propostas de nomenclatura (não definidos formalmente até a spec 04, que não faz parte desta fase).

## Observações sobre o mapeamento

- Todas as linhas acima cobrem, no mínimo, as categorias exigidas pela spec 01: dados do cliente, sócios/proprietários, solicitação, propriedades, produção, documentos, pareceres, workflow e assinatura.
- Nomes de componentes e endpoints são **propostas** para orientar as fases seguintes (Fase 2 em diante) — não são definições finais de API (isso cabe à spec 04, fora do escopo desta Fase 0).
- A entidade exata para "Pareceres" (`CreditAnalysis` vs. `Comment`) e para "comportamento/atualização cadastral" (campos de `Client` vs. `ClientProfile` dedicado) ficam como pontos a decidir na Fase 2 — ver OPEN QUESTIONS em `PROJECT_AUDIT.md` (OQ-A3) e `REQUIREMENTS.md`.
